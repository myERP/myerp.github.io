JSON Format

Vendor bills are represented as JSON objects which have the following keys:

{% include table-header.html %}
id {{ site.format.type.integer }} no yes Automatically assigned when creating customers
locked {{ site.format.type.boolean }} no no Indicates that the document can no longer be edited nor deleted.
sent {{ site.format.type.boolean }} no no Has the document been finalized or sent to the Customer.
sent_at {{ site.format.type.date }} no no The date the document has been finalized or sent to the Customer.
Format: {{ site.format.date }}
vendor {{ site.format.type.snippet }} no no The Snippet of the bill Vendor. None when the bill is paid to a customer or an employee (see payee_type).
Sent alone, without payee: a bill paid to its vendor stays paid to it, the new one. A bill paid to another vendor, its creditor, stays paid to the creditor, unless the new vendor is the creditor: the bill is then paid to its vendor, and follows later changes of it.
Where :
- id = vendor.id
- name = vendor.full_name
- user_code = vendor.user_code
payee_type {{ site.format.type.string }} no no Who the bill is paid to, as for an Expense, given by payee. Values: VENDOR, CUSTOMER, EMPLOYEE, NO_PAYEE.
Always returned: VENDOR for a bill paid to a vendor, NO_PAYEE for a bill without any payee.
Sent without payee: VENDOR has the bill paid to its vendor, NO_PAYEE leaves it without any payee. Left out, the bill keeps its payee, or is paid to the vendor sent.
The payee, a vendor, a customer or an employee, can change until the bill is paid, or at any time on a bill created from a bank entry (source_type bank_entry), whose payment follows the new payee. Otherwise the change is refused (NOT_EDITABLE).
payee {{ site.format.type.snippet }} no no Who the bill is paid to: a Vendor, a Customer or an Employee, as payee_type says. Always returned, except with NO_PAYEE.
- VENDOR: the vendor owed the bill. It is the vendor itself, unless the bill is owed to another vendor, its creditor, whose account then takes the payable. Sent alone, without vendor, it never changes the vendor: the same as the vendor, the bill is paid to its vendor; a bill without a vendor stays without one. To have one vendor both sell and be paid, send it as both vendor and payee.
- CUSTOMER: the bill then has no vendor, and its payable is posted on the customer's account, in the sales journal.
- EMPLOYEE: e.g. to refund an expense they paid. The bill then has no vendor, and its payable is posted on the employee's account.
Sent without payee_type, it is a vendor.
Where :
- id = the id of the vendor, customer or employee
- name = their full name
- user_code = their user code
billing_address {{ site.format.type.address }} no yes The billing address. The Contact address if any, the Vendor one otherwise.
paid {{ site.format.type.double }} no yes Total of the payments made on that bill.
unpaid {{ site.format.type.double }} no yes Remaining amount to be paid.
user_code {{ site.format.type.string }} no no The number assigned to this bill (i.e. VINV-002). If you don't specify a bill number, it will be automatically generated. 64 characters max.
ref_number {{ site.format.type.string }} no no The vendor's own reference number for this bill (e.g. their invoice number). 255 characters max.
this field can be cleared with a blank or empty string only, not a null value
date {{ site.format.type.date }} no no The date that will be printed.
Format: {{ site.format.date }}
Default: date of the day.
currency_iso_code {{ site.format.type.string }} no no The ISO Code of one of your Currencies
by default, the domain currency will be selected. 4 characters max.
employee_id {{ site.format.type.integer }} no no Id of the Employee assigned to that bill.
Default: the authenticated user.
order_lines {{ site.format.type.order_line }} no no An array containing the order lines of the bill.
shipping_address {{ site.format.type.address }} no yes The shipping address. The shipping Contact address if any, the User's one otherwise.
payment_terms {{ site.format.type.object }} no no Id of the Payment Term to apply on that bill. Will be used as a template to generate Settlements.
private_note {{ site.format.type.string }} no no A private note that won't be printed.
subtotal {{ site.format.type.double }} no yes Total before taxes and reduce. Based on the content of the order lines.
reduce_amount {{ site.format.type.double }} no yes Amount of the reduce, based on the subtotal and reduce rate.
tax_amount {{ site.format.type.double }} no yes Overall tax amount. Includes all taxes, discounts and reduce.
total {{ site.format.type.double }} no yes The final total the user needs to pay to the vendor. All included (taxes, discounts, reduce).
