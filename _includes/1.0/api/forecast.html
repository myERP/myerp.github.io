Forecasts

{% highlight bash %}Endpoint: {{ site.api.base_url }}{{ site.api.v1}}{{ site.resource.forecasts.url}}{% endhighlight %}

A Forecast is an amount of money expected to come in or go out of the bank accounts during one month, for a budget category and, optionally, a payee.
OneUp generates forecasts automatically from the history of the bank entries and documents. You can also create forecasts manually, once or recurring, then move, change or delete them.
Every forecast covers one calendar month. Its amount is what is still expected: the part already paid or due on documents is deducted from it.
Access to this endpoint requires the cash flow feature.

JSON Format

Forecasts are represented as JSON objects which have the following keys:

{% include table-header.html %}
id {{ site.format.type.integer }} no yes Automatically assigned when creating a Forecast.
due_date {{ site.format.type.date }} no no The last day of the month the forecast covers.
Format: {{ site.format.date }}
Set it on update to move the forecast to another month, see Updating a Forecast below.
amount {{ site.format.type.double }} no no The amount still expected this month, in the currency of the company.
Positive for money in, negative for money out.
On update, the sign is ignored: the direction of a forecast never changes.
base_currency_amount {{ site.format.type.double }} no yes The amount converted into the base currency.
currency_iso_code {{ site.format.type.string }} no yes The ISO code of the currency (ISO 4217).
budget_category {{ site.format.type.object }} no yes The budget category of the forecast. Contains id and name.
payee_type {{ site.format.type.string }} no yes The kind of payee of the forecast.
Allowed values: NO_PAYEE, CUSTOMER, VENDOR, EMPLOYEE, BANK_ACCOUNT.
payee {{ site.format.type.object }} no yes Who the money comes from or goes to. Contains id, name and user_code.
null when payee_type is NO_PAYEE.
user_code {{ site.format.type.string }} no yes Not used by forecasts, always null.

Creating Forecasts

A POST on {{ site.api.v1}}{{ site.resource.forecasts.url}} creates a manual forecast, once or recurring. The request does not use the format above, but the following keys:

Field Name Type Mandatory Description
type {{ site.format.type.string }} yes The direction of the forecast.
Allowed values: IN (money in), OUT (money out).
budget_category {{ site.format.type.object }} yes The budget category of the forecast. Only its id is read, and it must exist.
amount {{ site.format.type.double }} yes The amount expected for each occurrence, as a positive number. The direction is given by type.
start_date {{ site.format.type.date }} yes The date of the first occurrence. The forecast covers the month of this date, and keeps its day of the month.
Format: {{ site.format.date }}
frequency {{ site.format.type.string }} yes How often the forecast recurs.
Allowed values: ONCE, MULTIPLE_TIMES_A_MONTH, EVERY_MONTH, EVERY_TWO_MONTHS, EVERY_THREE_MONTHS, EVERY_FOUR_MONTHS, EVERY_FIVE_MONTHS, EVERY_SIX_MONTHS, EVERY_SEVEN_MONTHS, EVERY_EIGHT_MONTHS, EVERY_NINE_MONTHS, EVERY_TEN_MONTHS, EVERY_ELEVEN_MONTHS, EVERY_TWELVE_MONTHS.
MULTIPLE_TIMES_A_MONTH creates one forecast a month, like EVERY_MONTH.
occurrences {{ site.format.type.integer }} yes, unless frequency is ONCE The number of forecasts to create, the first one included. Ignored when frequency is ONCE.
Occurrences after the end of the sixth month from today are not created.
payee_type {{ site.format.type.string }} yes, when payee is given The kind of payee of the forecast.
Allowed values: NO_PAYEE, CUSTOMER, VENDOR, EMPLOYEE.
Default: NO_PAYEE.
payee {{ site.format.type.object }} yes, unless payee_type is NO_PAYEE or not given Who the money comes from or goes to. Only its id is read, and it must be an existing customer, vendor or employee, as given by payee_type.
action {{ site.format.type.string }} no What to do with the forecasts that already exist, see Existing Forecasts below.
Allowed values: CREATE, REPLACE, MERGE.
Default: CREATE.

The response is the array of the forecasts created or updated, in the format above.

{% highlight bash %} POST {{ site.api.v1}}{{ site.resource.forecasts.url}} { "type": "OUT", "budget_category": { "id": 7 }, "amount": 1200.00, "start_date": "2026-12-05", "frequency": "EVERY_MONTH", "occurrences": 3 } {% endhighlight %}

Existing Forecasts

Forecasts that already exist for the same budget category, payee and direction, from the month of start_date onwards, conflict with the new ones. A forecast without a payee only conflicts with forecasts without a payee. The action says what to do with them:

  • CREATE: if there is no such forecast, the new forecasts are created. Otherwise nothing is saved, and the request is refused with error 3029. The error details list the conflicting forecasts (existing) and what the request would give with REPLACE (replace) and with MERGE (merge), so the choice can be shown before sending the request again. Forecasts that would be new have the id 0.
  • REPLACE: every conflicting forecast is deleted, including those after the last new occurrence, then the new forecasts are created.
  • MERGE: in a month that already has a forecast, the new amount is added to it, and its day of the month becomes the one of start_date. In the other months, a new forecast is created.

Updating a Forecast

A PUT on {{ site.api.v1}}{{ site.resource.forecasts.url}}/{id} changes one forecast, whether it was generated by OneUp or created manually. Only these keys are read:

  • amount: the new amount still expected this month. The part already paid or due is kept.
  • due_date: any date in another month moves the amount still expected to that month. It is added to the forecast of that month for the same budget category, payee and direction if there is one, or makes a new forecast otherwise. The updated forecast keeps only what is already paid or due. A date in the same month changes nothing.

The response is the updated forecast.

Stopping a Series

A PUT on {{ site.api.v1}}{{ site.resource.forecasts.url}}/{id}/cancel_series, with an empty body, deletes this forecast and all the forecasts of the following months for the same budget category, payee and direction. To delete only this forecast, use DELETE on {{ site.api.v1}}{{ site.resource.forecasts.url}}/{id}.

Available Methods

HTTP Verb Endpoint Action
POST {{ site.resource.forecasts.url}} Create one or several forecasts, see Creating Forecasts
GET {{ site.resource.forecasts.url}}/{id} Retrieve a forecast
PUT {{ site.resource.forecasts.url}}/{id} Change the amount of a forecast or move it to another month, see Updating a Forecast
DELETE {{ site.resource.forecasts.url}}/{id} Delete a forecast
PUT {{ site.resource.forecasts.url}}/{id}/cancel_series Delete a forecast and the following ones of its series, see Stopping a Series

Listing forecasts (GET on {{ site.resource.forecasts.url}}) and deleting several at once are not available.
