Reconciliations

{% highlight bash %}Endpoint: {{ site.api.base_url }}{{ site.api.v1}}{{ site.resource.reconciliations.url}}{% endhighlight %}

This API doesn't handle PUT requests.

Reconciliations link a Bank Entry to an accounting document, confirming that the bank transaction and the document represent the same financial event.

You must provide both a bank_entry_id and a document_id with its document_type when creating a reconciliation.
Deleting a reconciliation unreconciles the document from the bank entry and updates the bank entry status accordingly.

JSON Format

Reconciliations are represented as JSON objects which have the following keys:

{% include table-header.html %}
id {{ site.format.type.integer }} no yes Automatically assigned when creating a Reconciliation.
bank_entry_id {{ site.format.type.integer }} yes yes Id of the Bank Entry being reconciled.
document_id {{ site.format.type.integer }} yes yes Id of the document being reconciled to the bank entry. The referenced resource depends on the document_type (see below).
document_type {{ site.format.type.string }} yes yes Type of the document being reconciled. Accepted values:
- bank_payment
- bill_payment
- sales_receipt
- expense
- bank_transfer
document_name {{ site.format.type.string }} no no Human-readable code of the reconciled document (e.g. IPAY-025). Automatically derived from the document.
reconciled_amount {{ site.format.type.double }} yes yes Amount matched between the bank entry and the document.
Must be positive and not exceed the bank entry's unreconciled amount.
auto_reconciled {{ site.format.type.boolean }} no no Indicates whether this reconciliation was created automatically by the system.
accounting_entry_code {{ site.format.type.integer }} no no Code of the related accounting entry generated by this reconciliation.

Reconcilable Document Types

The document_type field determines which resource the document_id refers to and what constraints apply when creating a reconciliation.

bank_payment

Reconciles a Bank Entry with an invoice Payment (user_code: IPAY-xxx).
Use this type to confirm that a credit on the bank statement matches a payment recorded against a customer invoice.
The bank entry must be a positive amount (credit). The reconciled_amount cannot exceed the payment amount.

FieldValue
document_typebank_payment
document_idId of a Payment resource.
document_nameAutomatically set to the payment's user_code (e.g. IPAY-025).
{% highlight bash %}{ "id": 156, "bank_entry_id": 353, "document_id": 25, "document_type": "bank_payment", "document_name": "IPAY-025", "reconciled_amount": 330.00, "auto_reconciled": false, "accounting_entry_code": 26243 }{% endhighlight %}

bill_payment

Reconciles a Bank Entry with a Bill Payment (user_code: BPAY-xxx).
Use this type to confirm that a debit on the bank statement matches a payment recorded against a vendor bill.
The bank entry must be a negative amount (debit). The reconciled_amount cannot exceed the bill payment amount.

FieldValue
document_typebill_payment
document_idId of a Bill Payment resource.
document_nameAutomatically set to the bill payment's user_code (e.g. BPAY-028).
{% highlight bash %}{ "id": 157, "bank_entry_id": 354, "document_id": 28, "document_type": "bill_payment", "document_name": "BPAY-028", "reconciled_amount": 99.00, "auto_reconciled": false, "accounting_entry_code": 26244 }{% endhighlight %}

sales_receipt

Reconciles a Bank Entry with a Sales Receipt (user_code: REC-xxx).
Use this type to confirm that a credit on the bank statement matches a direct income collected without going through an invoice.
The bank entry must be a positive amount (credit). The reconciled_amount cannot exceed the sales receipt's total_amount.
Once reconciled, the sales receipt's bank_reconciled field is set to true.

FieldValue
document_typesales_receipt
document_idId of a Sales Receipt resource.
document_nameAutomatically set to the sales receipt's user_code (e.g. REC-012).
{% highlight bash %}{ "id": 158, "bank_entry_id": 355, "document_id": 12, "document_type": "sales_receipt", "document_name": "REC-012", "reconciled_amount": 120.00, "auto_reconciled": false, "accounting_entry_code": 26245 }{% endhighlight %}

expense

Reconciles a Bank Entry with an Expense (user_code: EXP-xxx).
Use this type to confirm that a debit on the bank statement matches a direct outgoing payment recorded without going through a vendor bill.
The bank entry must be a negative amount (debit). The reconciled_amount cannot exceed the expense's total_amount.
Once reconciled, the expense's bank_reconciled field is set to true.

FieldValue
document_typeexpense
document_idId of an Expense resource.
document_nameAutomatically set to the expense's user_code (e.g. EXP-008).
{% highlight bash %}{ "id": 159, "bank_entry_id": 356, "document_id": 8, "document_type": "expense", "document_name": "EXP-008", "reconciled_amount": 59.99, "auto_reconciled": false, "accounting_entry_code": 26246 }{% endhighlight %}

bank_transfer

Reconciles a Bank Entry with a Bank Transfer (user_code: BTRF-xxx).
Use this type to confirm that a bank statement line corresponds to an inter-account transfer recorded in OneUp.
The bank entry can be either positive (credit) or negative (debit) depending on the side of the transfer being reconciled (to or from). The reconciled_amount cannot exceed the relevant side's amount.

FieldValue
document_typebank_transfer
document_idId of a Bank Transfer resource.
document_nameAutomatically set to the bank transfer's user_code (e.g. BTRF-007).
{% highlight bash %}{ "id": 160, "bank_entry_id": 357, "document_id": 7, "document_type": "bank_transfer", "document_name": "BTRF-007", "reconciled_amount": 5000.00, "auto_reconciled": false, "accounting_entry_code": 26247 }{% endhighlight %}

Available Filter Fields

{% include table-header-filter.html %}
id Filter by one or multiple ids (e.g. ?id=1,2,3).
bank_entry_id Filter by one or multiple bank entry ids (e.g. ?bank_entry_id=1,2,3).
document_id Filter by one or multiple document ids (e.g. ?document_id=1,2,3).
document_type Filter by one or multiple document types among:
- bank_payment
- bill_payment
- sales_receipt
- expense
- bank_transfer
(e.g. ?document_type=bank_payment,expense).
