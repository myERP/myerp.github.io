Address

In OneUp, addresses are used at several places. Accounts, Suppliers, Contacts... So, in the API, addresses are embeded into their own JSON format, and follow the same rules everywhere.

JSON Format

Addresses are represented as JSON objects which have the following keys:

{% include table-header.html %}
street_line1 {{ site.format.type.string }} no no First line of the address. 255 characters max.
street_line2 {{ site.format.type.string }} no no Second line of the address. 255 characters max.
street_line3 {{ site.format.type.string }} no no Third line of the address. 255 characters max.
postal_code {{ site.format.type.string }} no no The zip code of the address. 128 characters max.
city {{ site.format.type.string }} no no The city of the address. 128 characters max.
country {{ site.format.type.string }} no no The country of the address. 128 characters max.
locality {{ site.format.type.string }} no no The localisaton of the address (limited to the one from the country selected). 255 characters max.
short_locality {{ site.format.type.string }} no yes The short code for the Country. 10 characters max.
full_address {{ site.format.type.string }} no yes The full formated adress as it should appears on documents

Order Line

Order lines are product or service lines that are embeded within sales or purchases documents. They contain infos like price, quantity, description, etc...
While adding, removing or updating an order line, related values (such as total, tax amount...) on the contextual document will be updated accordingly.

JSON Format

Order lines are represented as JSON objects which have the following keys:

{% include table-header.html %}
id {{ site.format.type.integer }} no yes Automatically assigned
item_id DEPRECATED {{ site.format.type.integer }} yes for sales documents, no for purchase documents no Deprecated. See item.
Id of the ordered Product or Service.
item {{ site.format.type.object }} yes for sales documents, no for purchase documents no The ordered Product or Service. Send at least its id to set it; the full object is returned when reading.
For purchase documents, at least one of item, accounting_account or budget_category is required. Not editable once the line has been created.
accounting_account_id {{ site.format.type.integer }} no no Only for purchase documents. Id of the ordered Accounting Account. Alternative to accounting_account.
accounting_account {{ site.format.type.account }} no no Only for purchase documents. The ordered Accounting Account. Send at least its id to set it; the full object is returned when reading. Alternative to accounting_account_id.
For purchase documents, at least one of item, accounting_account or budget_category is required. Not editable once the line has been created.
budget_category {{ site.format.type.object }} no no Only for purchase documents. The ordered Budget Category. Contains id and name. Send at least its id to set it.
For purchase documents, at least one of item, accounting_account or budget_category is required. Not editable once the line has been created.
description {{ site.format.type.string }} no no A description of the ordered Product or Service.
Default: The Product or Service default description
quantity {{ site.format.type.double }} no no The ordered quantity.
Default: 1.00
unit_price_wt {{ site.format.type.double }} no no Unit Price before Taxes
Default: The Product or Service default sales price
discount_rate {{ site.format.type.double }} no no Discount rate for this line.
Default: 0.00
tax_id {{ site.format.type.integer }} no no Not available for US purchase documents.
Id of the Tax to apply. Alternative to tax.
tax {{ site.format.type.object }} no no Not available for US purchase documents.
The Tax to apply. Contains id. Alternative to tax_id.
is_taxable {{ site.format.type.boolean }} no no US sales documents only.
Shall the tax be applied ?
subtotal {{ site.format.type.double }} no yes Total before taxes, after discount.
discount_amount {{ site.format.type.double }} no yes The amount deducted by the discount.
tax_amount {{ site.format.type.double }} no yes The tax amount applied to this line.
total {{ site.format.type.double }} no yes Total including taxes.

Payment Term Line

Payment term lines are the installments of a Payment Term: which share of a document is due, and when. A Payment Term needs at least one of them, and their percentages must add up to 100.

JSON Format

Payment term lines are represented as JSON objects which have the following keys:

{% include table-header.html %}
id {{ site.format.type.integer }} no no Automatically assigned.
Send it back to update an existing installment, leave it out to create a new one.
percentage {{ site.format.type.double }} yes no The share (%) of the document due on that installment. Greater than 0 and up to 100.
days {{ site.format.type.integer }} no no The number of days between the document and that installment.
Default: 0
precision {{ site.format.type.string }} no no How the due date is worked out, once the days above have been counted:
due_on_receipt: that very day
x_days_before_end_of_month: x days before the end of that month
x_days_after_start_of_month: x days after the start of that month
x_days_before_end_of_next_month: x days before the end of the following month
x_days_after_start_of_next_month: x days after the start of the following month
Default: due_on_receipt
x_day {{ site.format.type.integer }} no no The x of the precision above. Ignored when the precision is due_on_receipt.
Default: 0
payment_method {{ site.format.type.string }} no no How that installment is expected to be paid:
check, debit_credit_card, cash, direct_debit_ach, wire_transfer, gift_certificate, credit_note, other
France only: tip, traite, meal_ticket, change_letter, billet_ordre
Default: check

Category Line

Category lines are embedded within Sales Receipts and Expenses. They split the total amount of a document across accounting accounts and budget categories, each optionally carrying a tax.
While adding, removing or updating a category line, the parent document's total_amount is updated accordingly.

JSON Format

Category lines are represented as JSON objects which have the following keys:

{% include table-header.html %}
id {{ site.format.type.integer }} no yes Automatically assigned.
total_amount {{ site.format.type.double }} yes no Line total including tax. The sum of all lines must be strictly positive.
sub_total_amount {{ site.format.type.double }} no no Line total excluding tax.
tax_amount {{ site.format.type.double }} no no Tax amount for this line.
price_mode {{ site.format.type.string }} no no Determines which amount field is authoritative when computing the tax breakdown. Values: withTaxes (uses total_amount), withoutTaxes (uses sub_total_amount).
tax {{ site.format.type.object }} no no The Tax to apply on this line. Contains id, name, and rate.
accounting_account {{ site.format.type.object }} no no The Accounting Account to assign this line to. Contains id, name, and number.
budget_category {{ site.format.type.object }} no no The budget category to assign this line to. Contains id and name.
notes {{ site.format.type.string }} no no A description for this line. 255 characters max.
